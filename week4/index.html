1

Harness

Input: a gameplay video. Output: game code, including the actions the player can take. A coding agent watches the video, writes a playable browser game, and then improves it over a few rounds of short feedback. The harness fixes everything except the agent, so the same experiment can be rerun with a different one.

Fixed per runthe video, the round 0 prompt, PROTOCOL.md, the feedback messages and their order, the workspace conventions, the Docker image and the evaluation
Swappedthe agent and its model, through a one file adapter in agents/
Tasksangrybird, 2 feedback rounds; tennis, 3 feedback rounds. The messages are the ones actually sent, for example "Your motion isn't continuous, and swinging left and right makes no difference."
Recorded per runevery prompt, the transcript, the game after each round, the evaluation, and the hash of every harness file
Reproducible meanssame inputs, same sandbox, same evaluation, several runs per configuration, compared as distributions. Not identical code.

3

Pair Data Curation

The real clip is the target. Player tracks, masks and joints are estimated with Grounding DINO, SAM 2.1 and ViTPose, the players are cut out, and a small library of their own poses is pasted back along the tracks they actually took. Two grades per clip.

lighttwo fixed poses per player, one per stroke side, translated along the real track, hard cuts between them
mediumsame routes and stroke intent, plus held frames, mismatched rhythm and short cross-fade ghosting
